Self-hosted document management for a personal or family archive. Scan, upload,
mail in or drop a file in a watched folder: docstore reads it (text layer or
OCR), links it to the people and companies it mentions, files it under a
document type, extracts the values you care about (an amount, a due date, a
contract number), and puts anything it is unsure about in a review queue. It
also tracks recurring documents and the periods that are missing, reminds you
before a paper expires, groups documents into dossiers, shares them through
public links, and exposes the whole library to an agent over MCP.

## Highlights

- Web upload, watched folder, IMAP mailbox, public upload link, API and CLI all
  end up in the same idempotent, resumable pg-boss job pipeline.
- Text extraction uses `pdftotext` when the PDF already has a text layer and
  Tesseract (`fra`+`eng`) otherwise, keeping word-level hOCR boxes for
  anchor-based extraction. Full-text search runs on a PostgreSQL `tsvector`
  covering the title, the extracted text and the free-text notes.
- A document type owns its detection signature, its layouts and their
  extraction rules (`regex`, `anchor`, `zone`), a title template and a filing
  preset. Applying it classifies and fills the document in one go.
- A weekly, monthly, quarterly, half-yearly or yearly type computes its own
  membership and flags the periods that never arrived. Expiry dates raise reminders at D-90 / D-30 / D-7.
- Anything below the confidence threshold (an unmatched issuer, a doubtful
  date, a possible duplicate) lands in the review queue with its reasons
  instead of being written to the document.
- Filing primitives: parties with roles and relations, hierarchical categories,
  tags, typed custom fields, dossiers, document relations, saved searches,
  physical archive numbers and locations.
- Sensitive documents are encrypted at rest (AES-256-GCM, per-object derived
  key), transparent on read and hidden from MCP unless the key allows it.
- A native MCP server on `/mcp` exposes search, classification, party, dossier,
  reminder, sharing and export tools behind scoped API keys.

## How it works

A file enters through one of the intake sources (upload, watched folder, IMAP,
upload link, API). Intake stores it, computes its SHA-256 (an identical file is
refused as a duplicate) and enqueues a `document.process` job. The pipeline then
runs four idempotent steps:

1. `extractText`: `pdftotext` if the PDF carries a text layer, otherwise
   Tesseract into hOCR, keeping the bounding box of every word.
2. `analyze`: an identifier pre-pass (SIREN, SIRET, VAT, IBAN, email, domain)
   proposes an issuer, a date is detected, document types are matched against
   their signature, then the applied type runs the extraction rules of its best
   layout and the `ingest` automations fire. Anything below the confidence
   threshold is recorded as a review reason instead of being written.
3. `render`: thumbnail and preview through `sharp`.
4. `finalize`: the document leaves `processing` for `active`, or for `review`
   when a blocking reason was recorded.

Replaying any step on an already processed document recomputes the same result,
so a failed ingestion can just be reprocessed. More detail:
[`docs/ingestion.md`](docs/ingestion.md) and
[`docs/document-types.md`](docs/document-types.md).

## Getting started

### Requirements

- [Bun](https://bun.sh) ≥ 1.3
- Docker, for the local PostgreSQL 18 (and for the production stack)
- Tesseract OCR with the `fra` and `eng` language packs
- Poppler (`pdftotext`)
- [portless](https://portless.sh) (`npm install -g portless`, Node 24+),
  optional: it gives the dev server a stable HTTPS URL on `*.localhost`.
  `bun run dev --no-portless` works without it

Tool paths come from the environment (`TESSERACT_PATH`, `POPPLER_PATH`,
`TESSDATA_PREFIX`) and are never hardcoded. Leave them empty when the binaries
are on `PATH`.

### Setup

```sh
bun install
cp apps/server/.env.example apps/server/.env   # fill in the secrets
bun run db:start                               # PostgreSQL on 127.0.0.1:5434
bun run dev
```

`apps/server/.env.example` documents every variable; the ones that matter are
`DATABASE_URL`, `DATABASE_URL_TEST`, `BETTER_AUTH_SECRET` and `APP_SECRET`
(32 characters minimum, `openssl rand -base64 32`).

`bun run dev` creates the database if needed, applies the migrations, seeds the
starter taxonomy, picks a free port for the API and hands the web app to
portless:

```
  docstore dev
  app        https://docstore.localhost
  api        http://127.0.0.1:3000 (proxied under https://docstore.localhost)
  health     https://docstore.localhost/health
  worktree   main
  database   docstore
  storage    …/docstore-v2/.data/storage
```

The Vite dev server proxies `/rpc`, `/api`, `/files`, `/health`, `/mcp`,
`/api-reference` and `/parties/*/logo` to the Hono server, using the same route
list as `docker/Caddyfile`. The browser then only ever talks to one host, like
in production: no CORS, no cross-port cookies, and share links open the address
they were built with.

### A demo library

```sh
bun run db:demo --reset
```

Generates a French household archive: parties with logos, document types with
layouts and extraction rules, ~50 PDFs (invoices, payslips, contracts, identity
papers) generated in code and ingested through the real pipeline, plus
dossiers, reminders, share links and a few documents left in review on purpose.
No fixture file is committed. The command prints the login it created
(`camille@example.com`).

### Everyday commands

| Command | What it does |
| --- | --- |
| `bun run dev` | Everything, on `https://docstore.localhost` |
| `bun run dev --no-portless` | Same, on plain `http://localhost:3001` |
| `bun run dev:server` / `bun run dev:web` | The raw servers, split-port, no proxy |
| `bun run db:demo` | Fill the current checkout's database with the demo library |
| `bun run db:reset --yes` | Drop, recreate, migrate and seed that database |
| `bun run check` | Biome (lint + format, auto-fix) — must be clean before committing |
| `bun run check-types` | `tsc` across every package |
| `bun test` / `bun run test` | Unit and integration tests |
| `bun run test:e2e` | Playwright, critical paths only |
| `bun run wt <branch>` | Create an isolated worktree (own URL, database, storage, port) |

Each git worktree is a full environment of its own: `bun run wt fix-ui` creates
`../docstore-v2.worktrees/fix-ui`, and `bun run dev` inside it serves
`https://fix-ui.docstore.localhost` on the `docstore_wt_fix_ui` database, so
several branches can run at the same time without colliding.

## Production

Docker Compose stack: Caddy (reverse proxy + TLS) → api + web → PostgreSQL 18.
Full instructions, backup, restore and update procedures live in
[`docker/README.md`](docker/README.md).

```sh
cp docker/.env.example docker/.env   # APP_SECRET, BETTER_AUTH_SECRET, POSTGRES_PASSWORD
bun run docker:build
bun run docker:up
```

`PUBLIC_URL` is frozen into the front-end bundle at build time: changing it
means rebuilding. `APP_SECRET` encrypts sensitive files, stored IMAP passwords
and share tokens, and cannot be rotated. See
[`docs/security.md`](docs/security.md) for the threat model and what it does
not cover.

## MCP

docstore ships a native MCP server (Streamable HTTP) on `/mcp`, so an agent can
search, classify, link and maintain the archive directly. Create an API key
first (Settings → API keys, scopes `read` / `write` / `sensitive`), then:

```sh
claude mcp add --transport http docstore https://docstore.example.com/mcp \
  --header "Authorization: Bearer dsk_…"
```

Full tool, resource and scope reference: [`docs/mcp.md`](docs/mcp.md).

## History

v1 (2020) was an ASP.NET Core application with its own encrypted store and the
idea of dossiers. It is kept on the `v1` branch, released as `v1.0`. It did the
job for five years, but classification stayed manual.

v2 (2026) is a full rewrite on a TypeScript stack, built around one question:
what can be decided automatically at intake, and what has to be reviewed by a
human? That is where document types with layouts, the extraction rules, the
confidence threshold and the review queue come from. Since the archive is now
readable by a machine, it also carries a native MCP server.
